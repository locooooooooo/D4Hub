# D4Hub 战斗统计面板需求文档

状态：需求迭代版；P0 屏幕估算链路已形成工程闭环，但未通过精度发布门槛和 Owner 验收

日期：2026-08-03

本文把用户提供的第三方战斗统计面板截图转化为 D4Hub 的分阶段需求。截图中的示例值只用于字段和布局参考，不是准确性目标，也不证明 D4Hub 可以从游戏内部取得同类数据。

## 1. 产品目标与边界

### 1.1 产品目标

在 D4Hub 现有可见屏幕捕获和 OCR 统计链路上，提供一个诚实标注数据质量的战斗统计 HUD：

- P0：对可见战斗文字提供多帧确认后的屏幕伤害估算，显示当前 DPS、最近 1 秒伤害、1 秒峰值和累计伤害；
- P1：在有标注数据和校准证据后，增加单次最高伤害、全会话/战斗段计时和战斗状态；
- P2：在明确可见且可重复识别的前提下，增加经验、金币效率和伤害构成；
- 所有阶段都必须把屏幕估算与精确战斗日志区分开，不用 UI 文案制造精度暗示。

### 1.2 安全边界

- 只读取用户屏幕上可见的 D4 客户端像素和用户主动提供的本地录像；
- 不读取游戏进程或内存，不注入，不检查游戏网络流量，不发送自动输入，不做自动拾取、自动施法或规避检测；
- 不把第三方闭源插件、逆向代码、游戏衍生二进制或未审核的游戏资产作为运行时依赖；
- 统计数据默认只在本地会话中存在，不上传用户屏幕、OCR 原文或战斗记录。

### 1.3 当前迭代的非目标

- 不承诺精确 DPS、精确命中日志、精确经验/金币账本或游戏内部伤害类型；
- 不在没有标注和跨环境回归证据时启用 HDR、任意 UI 缩放或未覆盖分辨率；
- 不把“能显示一个数字”作为字段验收，不用 `0` 代替未知、未实现或证据不足；
- 不为满足截图字段数量而同时扩大 OCR ROI、降低确认门槛或引入未经验证的模型。

## 2. 当前实现基线

以下结论以 2026-08-03 工作树中的实现为准，后续代码变更必须同步更新本节和验收记录。

| 能力 | 当前实现 | 需求口径 |
| --- | --- | --- |
| 实时视觉适配器 | `WindowsRealtimeOcrAdapter` 的能力声明为 `DamageOnly`，只读取校准的战斗文字 ROI | P0 屏幕估算；不是精确日志 |
| 默认校准 | `D4VisionCalibrationProfiles` 当前覆盖 `1080p/1440p + zh-CN + SDR`，默认只定义 combat 区域 | HDR、经验/金币、城镇指示器暂不视为已支持 |
| 采样与确认 | ViewModel 默认 OCR 最短间隔为 `0.6s`；伤害事件至少需要两帧一致证据，跟踪会按空间和时间去重 | 保留 fail-closed 规则；忙时/节流时丢帧是允许行为 |
| 已有伤害读数 | `RealtimeStatisticsSnapshot` 已暴露当前/最近伤害段平均 DPS、最近 1 秒伤害、1 秒峰值、累计伤害、已确认事件数、拒绝数和数据质量 | 这些字段可以进入 P0 HUD，但必须带“基线估算/证据不足”等状态 |
| 伤害会话 | `CombatDamageTracker` 已有约 4 秒静默切段和 `CombatSessionSummary.MaximumHit` | 单次最高伤害已接入 Snapshot/ViewModel/展开面板，以屏幕估算口径展示 |
| 经验/金币/材料模型 | Core 已有 `VisibleCounterTracker`，测试夹具可验证增量 | 当前实时 Windows OCR 适配器不返回 Counters，面板应显示“不可用” |
| 城镇与伤害分类 | Core 已有 `VisibleTownState`（Unknown/InTown/OutOfTown）三态滞回跟踪器和 `DamageClassification` 枚举；`SessionClock` 会话时钟与 `CombatActivityTracker` 战斗活跃滞回已实现并有独立回归 | 识别层（城镇 ROI/分类证据）未实现，面板城镇字段显示“不可用”；战斗状态按“最近 4 秒已确认伤害+滞回”候选规则展示 |
| 会话聚合 | `SessionDamageAggregator` 按事件 ID 幂等聚合，`RealtimeStatisticsSnapshot` 已暴露 `MaximumHit`、`SessionAverageDps`、`TotalRunSeconds`、城镇/未知时长、战斗活跃状态 | 全会话 DPS 分母为会话时钟有效运行时间；未通过 G2 标注录像验证前不得称为精确战斗起止 |
| HUD | `StatisticsOverlayWindow` 展开面板已接入最高伤害、全会话平均 DPS、总运行时间、城镇时间、战斗时间、城镇/战斗状态（带“暂无可信数据/不可用”占位），紧凑模式保留；布局尺寸更新为 320x250 | “完整 14 项面板”仍需 P2 资源与分类能力及 G3/G4 验收，未显示 P2 字段 |

现有实现和测试覆盖了数据契约、节流、单飞、失焦失效、重置以及不可用状态的部分行为；这不等于真实录像精度、跨环境稳定性或 Owner 验收已经完成。

## 3. 截图字段与阶段映射

截图的 14 项字段按产品优先级拆分如下。百分比和示例值不作为当前 P0 的承诺。

| 分类 | 指标 | 阶段 | 当前/目标语义 |
| --- | --- | --- | --- |
| 效率 | 非城镇经验/小时 | P2 | 仅使用已确认的可见经验增量和已确认的非城镇时长；无法确定状态时不计算 |
| 效率 | 金币/小时 | P2 | 仅使用已确认的可见金币增量和已确认的非城镇时长；不读取角色内部金币值 |
| 时间 | 总运行时间 | P1 | 统计会话的有效运行时间；暂停、失焦、等待游戏和错误区间的处理必须有明确回归结果 |
| 时间 | 城镇时间 | P1 | 只有城镇状态达到多帧确认才累计；未知状态不能默认为城镇或非城镇 |
| 时间 | 战斗时间 | P1 | 由已确认战斗段和状态规则计算，不直接把“最近 4 秒有伤害”称为完整战斗真相 |
| 伤害 | 战斗时每秒伤害 | P1 | 目标是已确认战斗段的平均 DPS；现有 `CurrentDps` 只能作为候选实现，尚未完成活跃状态、全会话/战斗段语义验收 |
| 伤害 | 全会话平均 DPS | P1 | 需要单独定义会话分母和暂停/城镇处理；不能复用现有 `CurrentDps` 的名称或语义 |
| 伤害 | 最高伤害数字 | P1 | 所有已确认事件的最大值；已有 Core 会话摘要，尚未接入实时 Snapshot/UI |
| 伤害 | 总伤害 | P0 | 已确认屏幕事件的累计值，不是游戏内部总伤害，对应现有 `TotalDamage` |
| 伤害构成 | 普通伤害 | P2 | 只有事件分类有独立证据时展示；未知分类不得强行归入普通伤害 |
| 伤害构成 | 持续伤害 | P2 | 只有事件分类有独立证据时展示；DoT 的识别方式需要标注数据支持 |
| 伤害构成 | 暴击伤害 | P2 | 只有事件分类有独立证据时展示；不以未经验证的颜色阈值作为确定事实 |
| 伤害构成 | 压制伤害 | P2 | 只有事件分类有独立证据时展示；不以未经验证的颜色阈值作为确定事实 |
| 伤害构成 | 压制暴击伤害 | P2 | 只有事件分类有独立证据时展示；分类规则必须与其他分类互斥 |

P0 额外保留“最近 1 秒伤害”和“1 秒峰值伤害”作为工程诊断字段；它们不是截图 14 项的新增承诺，但必须与总伤害分开验收。

其中“战斗时每秒伤害”和“每秒伤害”不能沿用截图中的模糊标签。产品 UI 必须使用明确名称，例如“当前伤害段 DPS”和“全会话平均 DPS”，并在数据质量区域显示“屏幕估算”。

## 4. 功能需求

### 4.1 数据质量和不可用状态

- **FR-QUAL-01** 只有通过两帧确认、空间/时间跟踪和当前拒绝规则的事件才能进入伤害汇总。
- **FR-QUAL-02** 采集状态至少区分：暂无可信数据、证据不足、实时采集、已暂停、等待游戏和采集错误。
- **FR-QUAL-03** 未实现能力显示“不可用”，已实现但暂无可信读数显示 `--` 或“暂无可信数据”；两者不得用同一个 `0` 表示。
- **FR-QUAL-04** HUD 必须显示数据质量级别或等价文案：基线估算、实验视觉、校准视觉、低覆盖或不可用。
- **FR-QUAL-05** 暂停、失焦、关闭全局监测、进入布局编辑和重置后，迟到的 OCR 结果不得写入当前会话。
- **FR-QUAL-06** 所有总额、DPS、峰值和百分比都必须能够追溯到本地会话中的已确认事件或已确认可见计数器变化。

### 4.2 P0 屏幕伤害估算

- **FR-DMG-P0-01** 显示当前/最近伤害段平均 DPS，明确说明其分母和“屏幕估算”属性；不把它标为全会话或精确战斗 DPS。
- **FR-DMG-P0-02** 显示最近 1 秒已确认伤害和历史 1 秒峰值，两者不得混用。
- **FR-DMG-P0-03** 显示已确认屏幕事件的累计伤害、已确认事件数和拒绝观测数。
- **FR-DMG-P0-04** 保留当前约 `0.6s` 最短采样间隔、单飞 OCR 和忙时/节流丢帧行为，不以降低确认门槛换取覆盖率。
- **FR-DMG-P0-05** 约 4 秒静默切分只用于伤害会话聚合；它是屏幕事件规则，不是游戏战斗状态的精确判定。
- **FR-DMG-P0-06** 高密度重叠、缺失小数点、异常单位、单帧极值和不连续候选必须拒绝或标记，不得直接计入。

### 4.3 P1 会话、战斗和时间

- **FR-TIME-P1-01** 新增可重放的会话时钟，明确运行、暂停、等待游戏、失焦和错误区间的计时规则。
- **FR-TIME-P1-02** 新增三态城镇判定：`InTown`、`OutOfTown`、`Unknown`。没有足够画面证据时必须保持 `Unknown`。
- **FR-TIME-P1-03** 城镇进入和离开都需要连续帧确认，并记录切换时间、证据来源和校准 profile；不能只凭单帧颜色阈值决定。
- **FR-TIME-P1-04** 战斗状态可以使用最近 4 秒已确认伤害作为候选规则，但必须有进入/退出滞回和“候选规则”文案。
- **FR-TIME-P1-05** 单次最高伤害和全会话平均 DPS必须与当前伤害段 DPS 分开建模，所有分母和时间范围在测试中固定。

### 4.4 P2 可见经验和金币效率

- **FR-EFF-P2-01** 只从明确可见、稳定定位且多帧确认的经验/金币读数建立基线和增量。
- **FR-EFF-P2-02** 经验/金币效率的小时分母只能使用已确认的非城镇有效时长；`Unknown`、暂停、失焦和等待游戏区间不得计入。
- **FR-EFF-P2-03** 计数器重置、场景切换、角色切换和 OCR 回退必须产生显式 change/reset receipt，不能把负增量静默当成收益。
- **FR-EFF-P2-04** 实时适配器未声明 `Counters` 能力时，经验、金币和材料必须显示“不可用”；测试夹具的 Counter 读数不等于实时识别完成。

### 4.5 P2 伤害构成

- **FR-BRK-P2-01** 每个已确认事件必须允许 `Unknown` 分类；分类失败时保留总伤害，但不补造分类。
- **FR-BRK-P2-02** 推荐使用互斥分类优先级：压制暴击、持续伤害、暴击、压制、普通伤害、未知。实现前必须固定并测试该优先级，避免重复计入。
- **FR-BRK-P2-03** 颜色、OCR 前缀和模型输出只能作为可审计证据，不能仅凭未经标注的颜色阈值宣称暴击或压制。
- **FR-BRK-P2-04** 百分比默认针对“已分类伤害”计算，并同时显示分类覆盖率；覆盖率不足时显示“低覆盖”，不能声称构成完整或约等于 100%。

### 4.6 UI 展示

- **FR-UI-01** 继续复用 `StatisticsOverlayWindow`，保留紧凑模式和展开模式；P0 展开模式只展示已实现的伤害字段及质量状态。
- **FR-UI-02** P1/P2 字段只有在对应数据能力和质量门槛通过后才加入完整面板；未实现字段显示“不可用”，不得隐藏能力缺口。
- **FR-UI-03** 紧凑/展开切换使用现有设置或明确 UI 命令，切换不应重置统计会话。
- **FR-UI-04** 面板位置沿用现有 HUD 校准和窗口生命周期规则；拖拽、点击穿透、置顶和失焦行为须有独立验收证据。
- **FR-UI-05** 数值继续使用 `DiabloNumberFormatter` 的万/亿/兆/京格式；原始值、单位换算和零值显示必须有 Core 测试覆盖。

## 5. 数据模型与接口约束

### 5.1 当前接口不能被误读

当前 `RealtimeVisionReadout` 已预留 Counters、Progress、Buffs 和 Map 集合，但接口预留不代表活动适配器已经实现。活动 Windows OCR 适配器的 `Capabilities` 是 `DamageOnly`，因此实时面板必须根据能力声明显示“不可用”。

当前 `RealtimeStatisticsSnapshot` 的 `CurrentDps` 是快照选取的当前/最近伤害段平均 DPS，`RecentOneSecondDamage` 是最近一秒窗口，`PeakOneSecondDamage` 是该伤害段历史峰值。它没有独立表达“全会话 DPS”或“当前段仍活跃”，新增这两种语义时必须增加独立字段和独立测试，不能改名复用。

### 5.2 推荐的增量模型

新增字段前先固定以下语义，避免用多个 `bool` 把未知状态误写成否定状态：

```csharp
public enum VisibleTownState
{
    Unknown,
    InTown,
    OutOfTown
}

public enum DamageClassification
{
    Unknown,
    Normal,
    DamageOverTime,
    Critical,
    Overpower,
    OverpowerCritical
}
```

建议在事件或事件旁路证据中保存 `DamageClassification`、分类证据和分类 profile，而不是直接把未经验证的颜色猜测写成确定的 `DamageHitFlags`。Snapshot 需要分别保存数值、时间范围、覆盖率和质量状态；任何未来的 `ExperiencePerHour`、`GoldPerHour` 和分类百分比都必须能表示“不可用/未知/低覆盖”。

### 5.3 状态机要求

未来的状态跟踪器输入为已确认伤害事件、城镇候选观测、会话时钟和暂停/失焦事件，输出为：

- `VisibleTownState` 及进入/退出证据；
- 当前伤害段是否活跃；
- 有效运行时间、已确认城镇时间、已确认非城镇时间和未知时间；
- 当前伤害段 DPS、全会话 DPS 和对应的时间分母。

任何输入证据不足时，状态机应保留未知或上一状态并等待滞回确认，不能用默认值静默填充。

## 6. 技术方案

### 6.1 已确认的 P0 方案

```text
前台 D4 可见帧
  -> 校准的 combat ROI
  -> Windows zh-CN OCR
  -> 受限中文单位数字解析
  -> 空间/时间跟踪与多帧一致性
  -> 已确认屏幕事件
  -> 当前 DPS / 最近 1 秒 / 1 秒峰值 / 累计伤害
  -> 数据质量与状态文案
```

P0 继续使用 WPF + .NET 8、`RealtimePanelViewModel`、`RealtimeStatisticsSession`、`CombatDamageTracker` 和 `DiabloNumberFormatter`。实验 Paddle/ONNX 管线只能作为显式实验或离线探针，初始化或推理失败必须回退 Windows OCR，不能直接替换默认基线。

### 6.2 P1/P2 方案约束

| 能力 | 推荐方向 | 进入实现前的前置条件 |
| --- | --- | --- |
| 城镇状态 | 校准 ROI + 多帧模板/特征；模型分类器作为后续候选 | 需要真实进入/离开城镇录像、正负样本、SDR profile 和误报/漏报记录 |
| 经验/金币 | 独立计数器 ROI + `VisibleCounterTracker` | 需要可见读数的基线、增量、重置和遮挡样本；只接受可见变化 |
| 伤害分类 | OCR 文本、空间关系和视觉证据的组合 | 需要人工标注；颜色阈值不能单独作为发布依据 |
| HDR/缩放 | 独立 calibration profile | 未校准前明确不支持，不复用 SDR 阈值 |
| 数据导出 | 本地 JSON/CSV 会话证据 | 明确原始帧、OCR 文本和脱敏策略；不上传用户数据 |

## 7. 实施路线与交付物

### P0：冻结屏幕估算契约

1. 固定当前 DPS 四项指标的名称、分母、数据质量和不可用文案。
2. 为 P0 生成一组可重放的正向、拒绝、单帧不足、重复命中、静默切段和错误回执夹具。
3. 保持 `0.6s` 采样下的单飞、节流、失焦失效和重置行为。
4. 在 UI 中明确“屏幕估算”，不显示尚未接入的最高单次伤害、计时、效率和构成字段。

### P1：时间和会话语义

1. 增加全会话 DPS、单次最高伤害和会话时钟的独立模型与测试。
2. 先实现 `Unknown/InTown/OutOfTown` 状态，再讨论效率统计；没有证据时不得默认非城镇。
3. 用真实录像验证暂停、失焦、城镇切换、战斗间隙和损坏帧，并保留切换回执。
4. 只有状态和时钟通过独立回归后，才把 P1 字段接入完整面板。

### P2：可见资源和分类

1. 为经验、金币和材料增加独立 calibration region、实时 adapter capability 和 reset receipt。
2. 为伤害分类建立人工标注集，输出分类覆盖率、未知量和拒绝原因。
3. 先在离线探针验证 precision、recall、重复计数和 P95 延迟，再接入实时 HUD。
4. 资源效率和伤害构成分别验收，不以其中一项通过替代另一项。

## 8. 验收门槛

### G0：契约和安全边界

- Core 和 Acceptance Tests 覆盖中文单位解析、两帧确认、重复折叠、静默切段、重置、不可用能力和数据质量文案；
- `git diff --check`、现有验证脚本和安全边界扫描通过；
- 代码、文档和 UI 都不出现内存读取、注入、自动输入或精确战斗日志暗示。

### G1：P0 屏幕估算工程验收

- 至少有真实 `1920x1080` SDR 中文战斗帧跑通 Windows OCR 生产适配器，并保留原始输入哈希、参数和结果回执；
- 1080p/1440p SDR profile 选择、combat ROI、0.6 秒采样、单飞和错误/回退行为可重放；
- HUD 能显示当前伤害段 DPS、最近 1 秒、1 秒峰值、累计伤害、质量级别和状态；
- 该门槛只证明链路和契约，不得把结果发布为精确 DPS。

### G2：P1 时间和会话验收

- 统一验证当前伤害段 DPS、全会话 DPS、单次最高伤害和最近 1 秒/历史峰值的分母与时间范围；
- 城镇进入、离开、未知、暂停、失焦和等待游戏都有状态切换回执；
- 战斗起止误差目标不超过 `0.5s`，但必须基于标注录像测量，不能由代码常量直接推导通过；
- 没有证据的区间按未知处理，不能进入非城镇效率分母。

### G3：P2 资源与分类验收

- 经验/金币只接受可见计数器变化，覆盖基线、增量、重置、遮挡和场景切换；
- 伤害分类在人工标注集上达到事件 precision 和 recall 各至少 `90%` 后，才允许使用分类统计文案；
- 孤立伤害文字解析准确率目标至少 `95%`，重复计数膨胀率不超过 `2%`；
- 分类统计同时显示已分类覆盖率，未知量不能被静默分配到普通伤害。

### G4：UI 和发布验收

- 展开面板只有在 G2/G3 对应能力通过后才显示截图中的完整 14 项；
- 紧凑/展开切换、位置校准、点击穿透、置顶、失焦和窗口生命周期均有 UI 证据；
- 1080p、1440p、窗口化、黑边、UI 缩放、损坏帧和 HDR 的支持矩阵有明确结果；未支持项保持不可用；
- G0-G3 通过后仍需 Owner 验收，Owner 验收未发生时不能称为稳定发布。

## 9. 风险与回退

| 风险 | 影响 | 回退 |
| --- | --- | --- |
| 高密度战斗文字重叠或小数点丢失 | 总伤害和 DPS 偏差 | 拒绝候选、降低覆盖率并显示证据不足；不降低多帧确认门槛 |
| 城镇状态误报 | 非城镇效率分母失真 | 保持 `Unknown`，暂停效率计算；不把未知强行计入任一侧 |
| 颜色/HDR/UI 缩放漂移 | 分类和区域识别错误 | 使用独立 profile；未校准环境保持不可用 |
| 计数器重置或场景切换 | 经验/金币增量虚高 | 记录 reset receipt，重建基线，不计入收益 |
| 新模型延迟或推理失败 | 采样堆积、UI 卡顿或结果污染 | 实验管线独立启用并永久回退 Windows OCR |
| 用户把屏幕估算当作精确日志 | 错误的配装和效率结论 | 固定“屏幕估算/低覆盖/不可用”文案，并在导出中保留质量字段 |
