## 2. 一句话目标

把 D4Hub 扩展为一个小而可信的玩家工具入口：它自身继续只提供本地 HUD 和受控工具能力，外部内容仅以经过人工审查的目录呈现，并由用户明确点击后在系统默认浏览器打开。

## 3. 已确认事实与硬边界

1. D4Hub 是 .NET 8 / WPF 本地 Windows HUD。
2. 不读取或写入游戏内存，不注入，不抓取游戏流量，不自动化输入或宏，不规避检测。
3. 现有显式 D2Core 导入是唯一网络请求；本议题的 MVP 不增加新的应用内网络请求。
4. 当前工作树存在未提交的初始实现；后续任务不得清理、回滚或覆盖这些改动。
5. 外部资源的可访问性、内容准确性和第三方安全性不由 D4Hub 控制。D4Hub 只能审查入口，不能替第三方背书。
6. 本议题当前只定义产品合同，不改产品代码、不签名、不上线、不发布。

## 4. 产品边界

### 4.1 D4Hub 自身能力

- 本地 HUD、构筑资料导入、离线缓存和本地用户状态。
- 资源目录的本地展示、分类、搜索或筛选。
- 对将要打开的资源名称、来源域名、地区、语言和第三方提示进行清晰展示。
- 用户点击后把一个经过严格校验的 HTTPS 地址交给系统默认浏览器。
- 对随安装包提供的资源清单进行本地结构、域名和完整性校验。

### 4.2 外部链接目录

- 仅保存最少的入口元数据，不复制文章、攻略、论坛帖子、新闻正文或用户内容。
- 不把第三方页面包装成 D4Hub 功能，不声称内容由 D4Hub 制作或验证正确。
- 不承诺站点持续可用，不代理登录，不保存第三方账号、Cookie 或 Token。
- 不把链接点击转化为推荐算法、广告画像或无限信息流。

### 4.3 明确非目标

- 不做内嵌 WebView、通用浏览器、信息流、网页阅读器或搜索引擎。
- 不抓取、聚合、缓存或改写第三方内容。
- 不调用第三方内容 API，不做后台可用性探测或启动时联网检查。
- 不做遥测、点击统计、个性化推荐、账号同步、评论或社交关系。
- MVP 不做付费排名、联盟链接、广告、赞助位或商业导流。
- 不允许用户提交任意 URL 后由 D4Hub 直接打开。
- 不在本阶段扩展到其他游戏；只为未来扩展保留数据边界。
- 不改变 D2Core 显式导入行为或现有安全边界。

## 5. 用户路径

### 5.1 首次进入

1. 玩家在 D4Hub 主工作台进入“资源”视图。
2. 页面显示有限分类及随安装包提供的资源，不发起网络请求。
3. 首次打开外部资源前，D4Hub 显示资源名称、完整来源域名和“将离开 D4Hub”的提示。
4. 玩家明确确认后，地址交给系统默认浏览器；D4Hub 不接收浏览器返回数据。

### 5.2 日常打开

1. 玩家按分类或语言/地区筛选。
2. 选择资源，先看到可辨识的来源域名、用途、语言、地区和最近人工复核日期。
3. 玩家点击打开；若清单条目、协议或域名校验失败，D4Hub 拒绝打开并提示清单问题。

### 5.3 不可用或地区受限

1. D4Hub 根据清单元数据标明“可能受地区限制”或“已知不可用”，但 MVP 不后台探测。
2. 若存在经审核的同类替代资源，可展示为独立条目，不静默重定向。
3. 资源失效报告入口在 MVP 中只指向项目维护渠道或说明页；不在应用内收集报告数据。

## 6. MVP 资源分类

| 分类 | 用户意图 | MVP 规则 |
| --- | --- | --- |
| 官方与新闻 | 查看官方公告、赛季和补丁信息 | 官方身份必须可验证；新闻站与官方来源分开展示 |
| 构筑与规划 | 打开暗黑核及其他构筑规划工具 | D2Core 的“外链打开”与既有“数据导入”必须在 UI 和代码路径上分离 |
| 攻略与资料 | 查阅机制、装备、词缀或任务资料 | 只链接入口或明确栏目，不复制正文；标注语言和最近复核日期 |
| 社区与论坛 | 进入讨论社区 | 明示第三方用户内容风险、登录边界和地区/语言 |

MVP 每类宜保留 1 至 3 个已审核资源，初始总量建议不超过 10 个。数量不是目标；每一项都必须能说明“为什么收录、由谁复核、何时复核、何时下架”。具体站点清单必须由 Owner 在 `QS-EXT-01` 中逐项批准。

## 7. 资源清单合同

每条资源至少包含：

- `resourceId`：稳定、不可复用的内部 ID。
- `gameId`：MVP 固定为 `diablo-iv`。
- `providerId`：独立于显示名的内容提供方 ID。
- `category`：受控枚举，不允许提供方自行扩张分类。
- `displayName`、`description`：D4Hub 自有的中性描述。
- `canonicalUrl`、`allowedHosts`：HTTPS URL 与精确主机白名单。
- `locales`、`regions`：语言和适用地区；未知必须明确为 `unknown`。
- `officialStatus`：`official`、`community` 或 `commercial-third-party`，不得混淆。
- `reviewedAt`、`reviewedBy`、`reviewMethod`：人工复核证据。
- `status`：`active`、`degraded`、`delisted`。
- `riskNotes`、`disclaimerKey`：地区、登录、付费或用户内容提示。
- `attribution`：来源名称及必要的商标/版权说明；不默认获得商标许可。

清单顶层至少包含 `schemaVersion`、`catalogVersion`、`generatedAt` 和 `entries`。模型应将游戏、提供方、分类和入口分开，避免把 D4Hub Core 写成某个站点的专用目录。

## 8. 收录、复核和下架规则

### 8.1 收录门槛

1. URL 使用 HTTPS，域名归属和站点身份可以人工核验。
2. 资源与 Diablo IV 玩家核心任务直接相关，不能只因流量或商业合作收录。
3. 页面没有已知恶意下载、仿冒登录、强制扩展安装或误导性跳转。
4. 来源、语言、地区、商业性质和登录要求可被清楚说明。
5. D4Hub 有权以文本方式链接，且不会复制受保护内容或未经许可的品牌素材。
6. 有可执行的复核周期和下架责任人。

### 8.2 质量复核

- MVP 在每次候选版本发布前人工检查：域名、HTTPS、主要用途、地区可达性提示和明显恶意行为。
- “最近复核日期”只表示入口当时被人工查看，不表示内容准确、无害或持续可用。
- 攻略内容的观点差异不由 D4Hub 排名解决；目录不展示未经定义的“权威评分”。
- 未来若引入自动探测，只能作为风险信号，不能代替人工收录和下架决定，并需单独批准新的网络行为。

### 8.3 立即下架条件

- 域名所有权变化、证书异常、恶意软件或钓鱼报告可信。
- 跳转至非白名单域名并要求登录、付款或下载。
- 来源要求移除，或出现明确的商标、版权、服务条款争议。
- 内容转为违法、欺诈、博彩或与收录目的实质无关。
- 长期失效且没有可核实的新官方地址。

MVP 下架通过随新版本发布的本地清单完成；在没有远程撤销能力时，严重风险需要项目安全公告和新的安装包。该响应时效风险必须在决定是否发布 MVP 前由 Owner 接受。

## 9. 桌面打开行为与安全

### 9.1 MVP 选择：系统默认浏览器

推荐使用系统默认浏览器，原因是浏览器承担沙箱、证书、密码管理、反钓鱼和用户登录隔离；D4Hub 不持有网页会话。内嵌 WebView 会引入运行时更新、Cookie、权限、下载、弹窗、导航拦截和第三方内容呈现责任，不属于最小闭环。

### 9.2 URL 防护

- 只允许清单中的固定 `https` 地址；拒绝 `http`、`file`、自定义协议、凭据段和任意用户输入。
- 解析 URI 后按标准化主机名与 `allowedHosts` 精确匹配；不接受字符串前缀匹配。
- 默认拒绝 IP 地址、短链、动态 DNS、同形异义域名和未经审核的子域名。
- 禁止加入追踪、推荐、联盟或用户标识参数；查询参数必须在条目中静态声明。
- 打开前始终展示真实主机名；条目显示名不能替代域名。
- 每次打开都必须来自可见的用户操作，不预取、不预览、不后台请求。

系统浏览器可能在打开后继续重定向，D4Hub 无法验证最终页面。因此白名单和人工复核只能降低风险，不能形成安全背书，免责声明必须明确这一点。

### 9.3 隐私

- MVP 不记录点击、停留、搜索、浏览器结果、设备标识或用户账号。
- D4Hub 不向资源 URL 附加来源参数，不提供第三方 SDK。
- 外部站点可能依据自身政策收集 IP、Cookie 或登录信息；打开前应说明数据处理从此由第三方控制。
- 任何未来的遥测、崩溃上报、个性化、同步或反馈收集都是新的数据处理，必须单独说明目的、字段、保存期限、关闭方式并获得 Owner 明确批准。

## 10. 品牌、内容和第三方合规

- “Diablo”“Diablo IV”及第三方站点名称、Logo 和商标归各权利人所有；D4Hub 不暗示隶属、认证、赞助或合作。
- MVP 优先使用中性文本名称，不复制第三方 Logo、截图、图标、文章摘要或页面设计。任何品牌素材使用需有许可依据和 Owner 决策。
- 链接描述必须由 D4Hub 编写，只陈述用途和来源，不把第三方营销文案当作事实。
- 不绕过登录、付费墙、地区限制、robots 规则或反自动化措施。
- API 接入、网页抓取、内容索引、摘要生成、镜像或缓存均不在 MVP；后续必须先核对服务条款、许可、频率、数据保留、安全和下架机制，再单独审批。
- 商业合作、付费排序和联盟收益若未来提出，必须清楚标注并与质量排序隔离；MVP 禁止。

## 11. 配置化与演进架构原则

### 11.1 MVP

- 清单作为随应用发布的只读 JSON 资源，构建时和启动时都进行 schema 校验。
- `D4Hub.Core` 只拥有提供方中立的数据模型、验证器和筛选规则；不打开浏览器，不依赖 WPF。
- `D4Hub.App` 只负责视图、明确用户操作和系统浏览器适配。
- 清单数据与 UI 分离；不得在 XAML 或 ViewModel 中散落具体 URL。
- 清单无可执行内容、脚本、模板表达式或动态程序集。

### 11.2 未来签名/更新，仅为架构预留

远程清单更新不属于 MVP。若 Owner 以后批准，应满足：

- 静态版本化清单与分离签名；客户端内置受信公钥，不把 TLS 当作唯一完整性保证。
- 防降级、版本单调、过期时间、密钥轮换、吊销和回滚规则。
- 下载、验签、schema 校验、域名策略校验全部通过后才原子替换缓存。
- 失败时保留最后一个已知有效版本；没有有效版本时回退到安装包清单。
- 更新清单只能改变声明式目录数据，不能下发代码、脚本、命令或任意协议 URL。
- 更新端点、请求频率、日志、代理行为和隐私说明必须另行批准。

### 11.3 多游戏与多提供方

- 用稳定的 `gameId` 和 `providerId` 建模，不以类名、目录名或 UI 文案隐式绑定 Diablo IV。
- 分类是 D4Hub 的受控词汇；提供方标签通过映射进入分类，不能扩大客户端权限。
- 每个游戏可以有独立清单和 Owner 审核集合，共用验证器但不共享默认收录。
- 添加新游戏是产品范围扩大，必须新建 Goal/Decision，不能仅靠新增 JSON 条目绕过治理。

## 12. 阶段路线

### M0：治理闭环，当前阶段

- Owner 回答 QuestionSheet，逐项批准或拒绝受保护决策。
- 固化首批不超过 10 个候选资源及人工复核证据。
- 确认 MVP 不增加应用内网络请求，并确认系统浏览器方案。
- 将批准结果写入 PKR Decision；未批准前 Task 保持 `backlog`。

### M1：本地目录 MVP

- 只读、随包资源清单；D4Hub Core 完成模型与拒绝式校验。
- WPF 资源视图显示分类、来源域名、地区/语言、复核日期和第三方提示。
- 用户明确点击后由系统默认浏览器打开。
- 无 WebView、远程更新、自动探测、API、爬取、遥测、个性化或商业排序。

### M2：可维护性

- 资源审查 SOP、版本化清单生成工具、失效报告处理流程。
- 可选的本地收藏、最近使用或用户隐藏设置需先明确本地数据权益和迁移策略。
- 仍不引入远程清单或第三方内容抓取。

### M3：受控远程更新

- 仅在 Owner 单独批准网络、签名、密钥管理、隐私和应急撤销方案后启动。
- 先做签名清单和最后有效版本回退，不做内容流或推荐算法。

### M4：多游戏/多内容提供方

- 以新 Goal 和独立资源审核集合扩展；先证明第二个游戏能复用合同，而不是提前抽象所有场景。

## 13. MVP 可验证验收准则

以下全部满足，M1 才能进入 Owner 验收；代码构建成功或历史 Task 的测试结果都不能替代这些证据。

1. 清单对全部条目执行 schema、稳定 ID、分类、HTTPS、精确主机白名单和重复项校验；非法样例明确失败。
2. 默认安装离线时能展示全部本地条目；进入资源页不产生网络请求。
3. 每个条目显示名称、真实域名、分类、来源性质、语言/地区、最近人工复核日期和第三方提示。
4. 只有可见用户点击才能调用浏览器适配器；列表渲染、筛选、悬停和启动不得打开或请求 URL。
5. `http`、自定义协议、IP、凭据 URL、短链、未知主机、未审核子域名和非法查询参数全部被拒绝。
6. MVP 不包含 WebView、浏览器 Cookie、第三方 SDK、点击遥测、API/爬取、远程清单下载或自动链路探测。
7. D2Core 外链入口和既有 D2Core 导入在命令、提示和测试中保持独立；外链打开不触发导入请求，导入边界不被扩大。
8. 首批每个资源都有 Owner 批准、复核证据和免责声明；未批准条目不进入发布清单。
9. 下架条目不会显示或打开；清单校验失败时安全失败并使用受信安装包版本，不接受部分非法清单。
10. Core 校验逻辑有离线单元/AcceptanceTests；WPF 有针对打开命令和可见提示的人工桌面验收记录。
11. `scripts/verify.ps1` 在候选实现上重新运行并通过，安全 API 扫描仍通过；这只构成测试证据，不自动构成 Owner 验收或发布。
12. Owner 明确记录验收 Decision 后才能将 Task 置为完成；签名、打包、上传、发布和远程配置仍需独立授权。

## 14. 风险与控制

| 风险 | MVP 控制 | 剩余风险 |
| --- | --- | --- |
| 钓鱼、域名接管或恶意重定向 | 精确白名单、人工复核、显示域名、系统浏览器 | 打开后的第三方重定向无法由 D4Hub 保证 |
| 资源失效或地区不可达 | 地区元数据、复核日期、替代条目、不静默跳转 | 随包清单无法即时撤销 |
| 第三方内容错误 | 来源分类、免责声明、不做权威评分 | 玩家仍可能依赖错误攻略 |
| 商标或内容争议 | 文本链接、中性描述、不复制素材、下架流程 | 链接和名称使用仍需逐项法务判断 |
| Hub 失控成信息流 | 条目上限、任务导向分类、无抓取/推荐/社交 | 后续商业诉求可能推动范围膨胀 |
