# D4Hub 核心功能产品 Backlog
状态：`proposed` / `backlog`

日期：2026-08-04

角色：产品经理整理，供大管家拆分后续开发任务

## 1. 结论

D4Hub 下一阶段应围绕一条清晰的核心闭环推进：

```text
识别当前构筑 -> 监测可见战斗与掉落 -> 辅助下一步决策 -> 本地复盘和改进
```

本轮提出 14 个新功能目标。它们是产品需求，不代表已经实现、已经测试或已经 Owner 验收。近期工作树中已有的实时战斗统计、材料拾取、地图 HUD、过滤器和嬗变提醒仍需按照各自的证据门槛单独验收。

## 2. 当前基线

| 已有能力 | 当前产品含义 | 不能直接推出的结论 |
| --- | --- | --- |
| 本地窗口识别、截图捕获和透明 HUD | 可以在前台 D4 窗口上展示本地提示 | 不等于支持所有分辨率、HDR 或缩放 |
| BD 指纹、装备槽词缀规则和多档案 | 可以根据可见技能栏匹配本地构筑资料 | 不等于能读取角色内部状态 |
| D2Core 显式导入、公共库和本地 JSON 缓存 | 用户可以主动导入并复用构筑数据 | 不扩大为后台抓取或自动同步 |
| 战斗统计与材料拾取模型、Windows OCR 适配器 | 已有屏幕估算链路和数据契约 | 不等于精确 DPS、完整拾取账本或发布级准确率 |
| 地图工具、POI 模型和世界事件时钟模型 | 有本地地图 HUD 的实现基础 | 不等于第三方地图内容持续可用或被 D4Hub 背书 |
| 过滤器集合、导入和复制 | 可以管理本地过滤码 | 不等于能自动修改游戏过滤设置 |
| 嬗变场景提醒 | 可以在可见场景满足条件时提醒 | 不等于自动操作或自动选择材料 |

## 3. 硬边界

1. 所有核心功能继续免费，本轮不引入账号、会员、广告或社交动作前置条件。
2. 只读取用户主动展示的本地屏幕、截图或录像；不读写游戏内存，不注入，不抓取游戏流量。
3. 不发送自动输入，不提供宏、自动施法、自动拾取、自动切换装备或规避检测能力。
4. 未验证的结果必须显示为“不可用”“暂无可信数据”“屏幕估算”或“低覆盖”，不得用 `0` 伪装成真实读数。
5. 远程资源、第三方内容和新网络请求不属于本 backlog 的默认授权范围；优先采用随包 JSON、本地缓存和系统浏览器外链。
6. 每个视觉能力都必须拥有 calibration profile、正负样本、失败回执和离线回放路径后，才允许接入默认实时 HUD。

## 4. 新功能清单

### F01：构筑差异诊断器

- 优先级：`P0`；预估：中
- 用户价值：玩家能快速看出当前档案与目标 BD 的技能、装备槽和关键词缀差在哪里，不必逐格人工比对。
- MVP：在已有构筑档案和当前可见识别结果之间生成差异列表；区分“未识别”“明确缺失”“已匹配”和“证据不足”；支持按槽位、技能、词缀筛选。
- 验收：同一组固定截图能稳定生成相同差异；无法确认的槽位不得显示为缺失；点击差异能定位到档案规则和目标值；不读取游戏进程。
- 依赖：`HudModels`、BD 档案、视觉置信度契约。

### F02：多构筑情境推荐

- 优先级：`P0`；预估：中
- 用户价值：同一角色拥有开荒、刷图、冲层等多个档案时，能知道当前更接近哪个档案，并避免误用错误过滤器。
- MVP：为每个档案增加用途标签、阶段标签和推荐过滤器关联；根据当前已确认的技能栏指纹给出候选排序；置信度不足时只显示“需要确认”。
- 验收：候选排序可由固定指纹夹具重放；低置信度不自动切换档案或过滤器；用户必须显式确认后才能将候选设为当前档案。
- 依赖：F01、现有 BuildProfile、LootFilterPreset。

### F03：装备和词缀变更对比

- 优先级：`P0`；预估：中
- 用户价值：玩家更换装备、升级词缀或调整淬炼后，可以看到这次变更影响了哪些目标规则。
- MVP：支持用户主动保存两个本地识别快照并生成槽位级 diff；显示新增、移除、数值变化和无法确认；允许写入本地“变更备注”。
- 验收：快照没有完整证据时标记未知；同一快照重复保存不产生重复变更；导出 JSON 不包含屏幕原图，除非用户明确选择附带。
- 依赖：F01、现有 JSON 持久化和截图学习数据。

### F04：战利品过滤器模拟器

- 优先级：`P0`；预估：中
- 用户价值：玩家在使用过滤码前就能理解它会保留什么、隐藏什么，减少导入后发现配置不合适的返工。
- MVP：解析本地过滤码并展示规则树；提供内置的物品样例；输出“显示/隐藏/条件冲突/无法解析”结果；支持复制修订后的过滤码，但不写入游戏。
- 验收：非法编码、未知字段和冲突规则有明确错误；模拟结果可由固定样例重放；任何复制动作只写入剪贴板，不调用游戏输入接口。
- 依赖：`LootFilters`、过滤码格式样例和版本化校验器。

### F05：本地刷图会话历史

- 优先级：`P0`；预估：中高
- 用户价值：玩家能保存每次本地刷图的开始、结束、有效时长、战斗估算和掉落摘要，比较哪种玩法更适合自己。
- MVP：提供手动开始/暂停/结束；把当前统计快照固化为只读会话记录；支持按日期、构筑、地图场景筛选；不上传任何会话。
- 验收：失焦、暂停、重置和异常退出的时间语义有单独状态；迟到 OCR 不得写入已结束会话；会话写入采用原子 JSON；未知字段保留未知而非补零。
- 依赖：`SessionStatistics`、`RealtimeStatisticsSession`、本地状态存储。

### F06：战斗时间线回放

- 优先级：`P1`；预估：高
- 用户价值：玩家能复查一次战斗中伤害峰值、拒绝观测、采样空窗和数据质量变化，知道 HUD 数字是否值得参考。
- MVP：保存脱敏后的事件时间线和 receipt，不默认保存原始画面；提供按时间拖动、事件筛选和拒绝原因查看；允许从本地录像重新生成同一报告。
- 验收：报告能显示 requested pipeline 与 active pipeline；单帧候选、重复折叠和低置信度事件不被误标为已确认；回放结果与离线探针 schema 一致。
- 依赖：`CombatProbe`、vision-replay、F05；必须先通过延迟和准确率门槛。

### F07：伤害构成分析

- 优先级：`P1`；预估：高
- 用户价值：在证据足够时，帮助玩家观察普通、暴击、压制和持续伤害的构成，而不是只看一个总 DPS 数字。
- MVP：允许 `Unknown` 分类；展示已分类覆盖率、各类累计和样本数量；分类证据可追溯到 OCR 文本、空间关系或已标注视觉特征。
- 验收：分类互斥，未知事件不会静默归入普通伤害；人工标注集上的 precision 和 recall 达到产品门槛后才能进入默认 HUD；覆盖不足时显示“低覆盖”。
- 依赖：战斗文字标注集、F06、`DamageClassification` 契约；不能只凭未经验证的颜色阈值上线。

### F08：可见资源效率面板

- 优先级：`P1`；预估：高
- 用户价值：玩家能比较不同刷图方式的金币、经验和材料效率。
- MVP：只统计已确认可见的计数器增量；以已确认的非城镇有效时长为分母；分别显示每分钟和每小时；场景切换、重置和未知状态暂停计算。
- 验收：负增量生成 reset receipt；未知城镇状态不计入非城镇分母；实时适配器没有 `Counters` 能力时显示“不可用”；不把测试夹具当作实时支持证据。
- 依赖：`VisibleCounterTracker`、城镇状态识别、F05；需要真实录像验证。

### F09：本地刷图路线和目标清单

- 优先级：`P1`；预估：中
- 用户价值：玩家可以为一次刷图设定目标 POI、事件和资源，不用在地图、笔记和 HUD 之间来回切换。
- MVP：从本地 POI JSON 创建目标清单；支持手动标记已完成、跳过和备注；在地图 HUD 中展示当前目标和剩余目标；不自动点击地图或游戏对象。
- 验收：清单与地图缩放、窗口移动和关闭重开后保持一致；未知 POI 不被误报为完成；目标数据版本化、可导入导出且不依赖网络。
- 依赖：`MapHudModels`、地图 HUD 位置校准和本地样例目录。

### F10：世界事件聚合与本地提醒

- 优先级：`P1`；预估：中
- 用户价值：把已审核的本地事件时钟、倒计时和目标清单集中到一个可读的 HUD，减少错过活动的情况。
- MVP：维护本地事件时间表；显示开始、剩余和已过期状态；允许用户手动关闭单个提醒；应用重启后恢复本地设置。
- 验收：时间来源、时区和版本在 UI 中可查；暂停、系统休眠和时钟跳变不会静默把事件标为准确；提醒只产生本地视觉/声音提示，不执行游戏输入。
- 依赖：`WorldEventClock`、`WorldEventEdgeTracker`、F09；外部网页持续可用性不作为验收前提。

### F11：视觉校准自检与支持矩阵

- 优先级：`P0`；预估：中
- 用户价值：玩家在使用前能知道当前分辨率、窗口模式、语言和显示模式是否被支持，也能快速定位为什么 OCR 没有数据。
- MVP：展示当前窗口尺寸、D4 前台状态、选中的 calibration profile、ROI、OCR 语言和能力开关；提供截图自检报告和失败原因。
- 验收：profile 缺失、语言包缺失、窗口失焦、ROI 越界和覆盖遮挡分别提示；不支持的环境明确不可用；报告可复制为不含原图的文本/JSON。
- 依赖：`VisionCalibrationCatalog`、`OverlayCapturePolicy`、现有视觉探针。

### F12：HUD 模块和场景预设

- 优先级：`P1`；预估：中
- 用户价值：玩家可以分别保存刷图、城镇整理、冲层和截图校准的 HUD 布局，不必反复拖动窗口。
- MVP：保存多个本地场景预设；每个预设控制战斗统计、地图、构筑提示和嬗变提醒的显示/位置/紧凑度；支持一键切换，但不根据游戏状态自动切换。
- 验收：预设切换不会重置统计会话；拖动、点击穿透、置顶和失焦规则与现有 HUD 一致；损坏预设能回退到默认模板；未支持模块不显示假数据。
- 依赖：现有 layout template、各 HUD 窗口生命周期和 F11。

### F13：构筑快照版本库

- 优先级：`P2`；预估：中
- 用户价值：玩家可以保存赛季、等级阶段和装备变化后的多个构筑版本，回看什么时候开始偏离目标 BD。
- MVP：本地保存构筑快照的版本号、来源、时间、阶段和用户备注；支持两个快照 diff；支持导出和删除；不自动同步到云端。
- 验收：快照包含来源和证据状态；删除后不会影响当前活动档案；相同来源与内容不会重复创建；导出文件不含账号、设备指纹或原始屏幕。
- 依赖：F03、F05、本地 JSON schema 迁移和备份恢复。

### F14：隐私安全导出与故障包

- 优先级：`P2`；预估：中
- 用户价值：玩家遇到 OCR、窗口定位或 HUD 布局问题时，可以生成一份可审计、可脱敏的本地诊断包。
- MVP：导出版本、环境支持矩阵、能力声明、错误 receipt、配置摘要和文件哈希；默认排除截图、OCR 原文、窗口标题中的角色信息和路径中的用户名；提供导出前预览。
- 验收：导出前逐项显示将包含/排除的字段；用户可以取消；诊断包能由验证器检查 schema 和哈希；没有网络上传、自动提交或隐蔽遥测。
- 依赖：F11、F05、本地数据字典和导入/导出 schema。

## 5. 推荐开发顺序

### 批次 A：先解决“看得懂、用得稳”

1. F11 视觉校准自检与支持矩阵。
2. F01 构筑差异诊断器。
3. F04 战利品过滤器模拟器。
4. F05 本地刷图会话历史。

批次 A 的目标是让现有功能的状态、证据和用户决策可见。没有 F11 和 F05，后续实时指标容易被误认为准确账本。

### 批次 B：形成“监测后能决策”的闭环

1. F02 多构筑情境推荐。
2. F03 装备和词缀变更对比。
3. F09 本地刷图路线和目标清单。
4. F10 世界事件聚合与本地提醒。
5. F12 HUD 模块和场景预设。

批次 B 只使用用户主动确认和本地数据，不自动替换档案、不自动操作游戏。

### 批次 C：在证据足够后扩展统计

1. F06 战斗时间线回放。
2. F07 伤害构成分析。
3. F08 可见资源效率面板。
4. F13 构筑快照版本库。
5. F14 隐私安全导出与故障包。

批次 C 依赖真实录像、人工标注、性能预算和独立验收。任何一项数据证据不足，都应保留为离线探针或“不可用”，不能为了字段完整而降低确认门槛。

## 6. 统一验收 Definition of Done

每个功能进入实现任务前，必须补齐以下内容：

- 明确用户路径、失败路径和不可用文案；
- 明确 Core 数据模型、持久化 schema 和迁移策略；
- 至少一组正向、拒绝、边界和恢复测试；
- 若涉及视觉识别，提供输入哈希、profile、参数和回放 receipt；
- 说明数据是否只保存在本地，以及导出是否包含原图/OCR 原文；
- 通过 `dotnet build -c Release`、对应测试、`git diff --check` 和安全边界扫描；
- 将“已实现”“技术验证”“Owner 验收”“已发布”分开记录。

## 7. 产品经理结论

推荐先立项 F11、F01、F04、F05 四项，作为下一轮 P0。它们能直接提高当前 D4Hub 的可理解性和可用性，并且不要求先承诺精确 DPS、经验账本、远程资源更新或第三方服务接入。F06-F08 属于高风险视觉统计，应等真实录像证据和标注集到位后再排入默认 HUD。
